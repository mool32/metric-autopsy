# Pre-registration v1 — confirmatory validation of metric-autopsy v0.3

**Status: DRAFT for approval by the project owner.** Nothing in this file is final until it is
approved. On approval: the engine, this file, the panel generator and the scoring script are
frozen under the tag `v0.3.0-prereg`, and the sha256 of this file is recorded in the tag
message and in `PROJECT.md`. After the tag, the engine and the protocol change only through
`validation/prereg/DEVIATIONS.md` (D-series, one entry per change: what, why, when, and which
results it touches). Every number cited from the validation comes from the scripts named here,
with the hashes from their JSON reports.

Scope: RNA only (scRNA-seq counts). Other modalities are out of v1.

---

## 1. What the validation tests

The claim under test is about the validator, not about any biology:

> On datasets whose truth is known by construction or by design, metric-autopsy v0.3 (frozen)
> (a) rarely certifies a claim that is false — false SUPPORTED on nulls, artifacts and useless
> metrics; (b) rarely gives a verdict that is wrong *given the design* — outside the set of
> verdicts that are correct for that design; and (c) commits to a definite verdict where the
> design makes the truth establishable, instead of retreating to INCONCLUSIVE.

(c) exists because a validator that never errs because it never commits is useless. Both axes are
primary.

The development set (`validation/probes/`) found the bugs and the fixes were developed against
it. It plays no part here. The panel below has no overlap with it: different generators,
different backgrounds (real data), different metrics where possible, and a blind assignment of
cases.

## 3. The panel

### 3.1 Backgrounds (real data; downloaded and hashed before the tag)

| ID | Source | Use |
|---|---|---|
| B1 | Human skin fibroblasts, 10x (CELLxGENE; the GATE 6 dataset in `DATASETS.md`, 179 donors) | null and injected-signal datasets built by drawing donors |
| B2 | Tabula Muris Senis, droplet (10x), one tissue with the most mice per age | mouse-level nulls; sex anchor R1 |
| B3 | Buettner et al. 2015, mESC sorted G1 / S / G2M, with ERCC (ArrayExpress E-MTAB-2805; accession to be verified on download) | cell-cycle and content anchors R2 |
| B4 | One FUCCI dataset (candidate: Mahdessian et al. 2021, U2OS, Smart-seq2; to be confirmed on download) | cell-cycle anchor R3 |

The panel needs network access to these sources (the hosts the owner is opening). If a source
is unavailable at freeze time, its cases are dropped *before* the tag and the drop is recorded
here; nothing is substituted after the tag.

Within one dataset, donors (mice) are drawn without replacement. Across the replicate datasets of
a condition donors are reused (B1 has 179); donor overlap between datasets is reported, and every
rate is recomputed on donor-disjoint subsets as a sensitivity analysis.

### 3.2 Cases

The **allowed set** is the set of verdicts that are correct *given the design*; anything outside
it is an error. A verdict is scored by its label, the text before " — " (SUPPORTED covers
"SUPPORTED (provisional until replicated)" and "SUPPORTED — replicated"); bracketed qualifiers
(parametric only, underpowered) do not change the label.

A case is **establishable** when an *oracle analysis* reaches the case's definite verdict with
power ≥ 0.9 in a pilot on B1/B2 resamples outside the panel seeds; the engine's **definite**
verdict is then expected. The oracle is told what the engine has to find out: it takes the
metric's validity as known, removes a planted capture loss with the true capture factor (not an
estimate), and applies to the per-replicate metric values the test the graded replicate rule
prescribes for the design, at the same alpha and SESOI. For a useless metric (N6) the oracle is
the valid metric of N1 facing the same injected signal. The oracle's power is the most a
validator could reach; the engine's own verdicts never decide establishability, which would
make decisiveness true by selection. Group labels in every generated dataset are neutral
(`A` / `B`), and the side that receives an artifact or a signal is drawn by the key.

**Nulls, artifacts and useless metrics** (false SUPPORTED is scored on all of them):

| ID | Construction (on B1 unless noted) | Allowed | Establishable → definite | Datasets |

| N2 | N1 + capture loss in one group: thinning to c = 0.5 (key); steps c = 0.9, 0.7, 0.3 | NOT SUPPORTED, INCONCLUSIVE, NO DETECTABLE EFFECT | c ≤ 0.5 with the pilot's donor count → NOT SUPPORTED (explained by depth) | **400** at 0.5; 100 per step |

### 3.3 Blind assignment

`panel.py --key-seed <seed>` builds every dataset of sections N and E from the backgrounds:
the seed decides which condition, dose, step and side each dataset belongs to, and the order of
dataset IDs. The **key seed is generated and held by the project owner** and never enters the
repository or this session before scoring. The script writes, for each dataset ID, the data and
a claim card (metric, groups `A`/`B`, estimand, replicate column, SESOI, controls or injected
signal); claim cards do not depend on the condition. Every claim card resolves the judgment
gates (`judgment_pending: false`: what each metric measures is known by design), binds the
metric and its control `pair_metric` from the same function with the analysed `gene_pair`, and
keeps the engine's defaults for everything it does not name. The truth is generated by
`panel.py`'s own code (binomial thinning as in seqgendiff, Gerard 2020, for signals and capture
loss), never by the engine's modules, so the code under test does not define the truth it is
scored against.

The frozen engine is run once per dataset ID, through the Python API with the claim card as the
pre-registration. Every run is in the run log (attempt counter), and the JSON reports and the log
are committed — with their sha256 in the commit message — **before** the key is revealed. Then
the owner reveals the seed and `score.py` decodes the conditions and computes the outcomes.
Anchors R1–R3 are not blinded (their truth is public); the engine is frozen before they are run.

## 4. Replicates and precision

At least 200 datasets per key null condition were asked for (±3 percentage points at a 5% rate).
The operating characteristics (section 6, `oc.log`) show that 200 cannot separate a calibrated
validator from one with double the error at the nominal rate of a two-sided α = 0.05 test, so key
null conditions get **400** datasets. If computation is short, conditions are dropped, not
replicates: N3 steps and the off-key E1 doses go first.

The panel is about 3,650 engine runs. Before the tag, one run is timed with the engine to be
frozen on simulated data of B1's size (`validation/probes/probe_sim.py`); if the panel does not
fit the compute available, conditions are dropped in the order above and the drop is recorded
here. A drop after the tag is a deviation (D-series).

## 5. Primary outcomes

Every rate is reported as k/n with its two-sided 95% Clopper-Pearson interval
(`metric_autopsy.stats.clopper_pearson`), per condition and pooled.

- **P1 False SUPPORTED** on nulls, artifacts and useless metrics (N1–N7): share of verdicts
  starting with SUPPORTED.
- **P2 Outside the allowed set**, all generated cases (N and E): share of verdicts not in the
  case's allowed set. An engine exception counts as outside the set.
- **P3 Decisiveness** on establishable cases: share of definite verdicts (anything but
  INCONCLUSIVE; an UNTESTED metric makes every effect claim INCONCLUSIVE). Also reported: share of
  *correct* definite verdicts.
- **P4 Per-gate sensitivity and specificity**:
  - GATE 1: flags the stratum with a capture loss (N2/N3 steps), and stays silent on N1;
  - GATE 2 / effect field: "explained by depth" on N2 at c ≤ 0.5; share of the effect retained on
    E1–E3;
  - GATE 4: PASS for the valid metrics of N1/E1, FAIL for N6a and N6c;
  - GATE 5: FAIL rate of the negative control on N1 (specificity); FAIL as "insensitive" for a
    blind metric in powered strata (sensitivity; one blind-metric arm of 100 datasets inside N6);
  - GATE 0: bias flags on the valid metrics (specificity); attenuation reported, never failed.
- **Dose–verdict curves** (E1 doses, N2 and N3 steps): share of each verdict with its interval.

## 6. Success criteria

Nominal levels: with α = 0.05 and a two-sided effect test, a calibrated validator gives about 5%
SUPPORTED on a null dataset whose metric is valid and whose judgment is resolved. The criteria are
set so that such a validator passes with probability ≥ 0.9 and one with double the error fails
with probability ≥ 0.95 (numbers from `oc.py`; two-sided 95% Clopper-Pearson bounds):

| Criterion | Rule | P(pass) for a sound validator | P(pass) for a worse one |
|---|---|---|---|
| **S1** false SUPPORTED, each key null condition (N1, N2 c=0.5, N5, N6c; n = 400) | upper bound ≤ 10% (= 2α) | 0.97 at a true rate of 5% | 0.02 at 10% |
| **S2** false SUPPORTED, pooled over N1–N7 (n = 2750) | upper bound ≤ 7% | 0.99 at 5% | 0.00 at 7.5% |
| **S3** decisiveness, pooled establishable cases (n ≥ 200) | lower bound ≥ 70% | 0.91 at a true 80% | 0.02 at 70% |
| **S4** outside the allowed set, pooled N and E (n = 3650) | upper bound ≤ 10% | 1.00 at 5% (0.53 at 9%) | 0.02 at 10% |

The proposal was "upper bound ≤ 7% for false SUPPORTED". With 200 datasets a calibrated
validator meets it with probability 0.12 (`oc.log`), so 7% is kept for the pooled rate (S2), where
n in the thousands gives it the power, and the per-condition bound is 2α (S1). Decisiveness ≥ 70% is kept as
proposed (S3): establishable cases are built for power ≥ 0.9, so a sound validator should be near
80–90%.

The validation **passes** only if S1–S4 all hold. Each failed criterion is reported with the
number that failed it; there is no rescue language and no re-run.

## 7. Secondary outcomes

Anchors R1–R3 (verdict against the allowed set, one by one); the four fields for each anchor;
replicate counts and design read from metadata; run time and memory per dataset.

## 8. Analysis plan

1. Tag `v0.3.0-prereg`; record the sha256 of this file and of `panel.py`, `score.py`.
2. Download the backgrounds; record their sha256; run the pilot with the oracle analysis of
   section 3.2 (which cases are establishable, SESOI for N1, key dose for E1) on resamples
   outside the panel seeds; commit it. The oracle is part of `score.py` and frozen with it.
3. The owner generates the key seed and runs `panel.py`; the dataset files and claim cards are
   hashed and committed (key withheld).
4. Run the engine once per dataset; commit the reports and the run log with their hashes.
5. The owner reveals the seed; run `score.py`; commit the scores. Then the flagship TMS case is
   run on v0.3, after the tag, so that the real case cannot have shaped the logic.

Nothing is excluded after step 3. A dataset the engine cannot process counts as an error (P2).

## 10. Decisions requested before the tag

1. **Approve S1–S4**, including 400 datasets per key null condition (instead of 200) and the
   split of the 7% bound into S1 (2α, per condition) and S2 (7%, pooled).
2. **Directional claims?** With SUPPORTED requiring the effect in the pre-registered direction,
   the nominal false SUPPORTED rate halves to 2.5% and S1 could tighten to 5%. It needs an engine
   change (a `direction` key in the pre-registration, and NOT SUPPORTED for a detected effect in
   the other direction) before the tag. Not included unless approved.
3. **Positive-control dose**: default `positive_control_dose = 2.0` (Spearman ≈ 0.34 between genes
   with ~7 counts per cell) and power threshold 0.8.
4. **Backgrounds B1–B4** and the FUCCI dataset choice, once the network is open.
5. **GATE 0's null** still shuffles genes within depth bins. The positive control's null now uses
   depth-matched thinned draws because the bin shuffle let a depth-only pair pass. Apply the same
   draw to GATE 0 before the tag, or keep it and record the limitation.
6. **GATE 0 and depth at scale.** In a B1-sized simulation (`validation/probes/p13_depth_bias_at_scale.log`)
   GATE 0 classifies depth halving as *bias* for log-normalized Pearson on a truly coupled pair
   once there are enough cells to resolve it: the CP10k ratio correlation in its null (probe p06)
   grows at lower depth, by 31–50% of the pair's signal at 800 cells per donor (FAIL in 0/4,
   1/4 and 4/4 datasets at 200, 400 and 800 cells per donor). By the current rule the metric is
   then invalid and the analysis stops. Yet with a capture loss of 0.5 in one group and no
   biology, the effect field alone never detects a difference at equal depth (0/10) and reaches
   NO DETECTABLE EFFECT in 8/10 (part 2 of p13). If B1 behaves the same, the panel's valid
   metric is declared invalid and every E case fails.
   (a) Keep the rule; choose a panel metric whose depth response is immaterial at B1's depth,
   checked in the pilot. (b) Make a depth or capture bias non-blocking when the pre-registered
   correction equalizes depth between the groups — reported, with the verdict resting on the
   effect at equal depth — while dropout and library-scale bias stay blocking; N2, E2 and E3 then
   measure exactly the risk this takes. Either way the change, if any, is made before the tag.
